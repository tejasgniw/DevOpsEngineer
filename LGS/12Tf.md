# Terraform (Conditional provisioning, data driven, single responsibility)

- Conditional services provisioning based on environment variables
- Maintained re-usable tf modules in a central repo. Higher-level modules call lower-level modules
- Single Responsibility: Each module handles one concern
- Dependency management: depends_on clauses ensure correct order
- Remote state in s3 with a statelock management done by the DynamoDB
- Environment-specific state: Each branch (dev, qa, prod) has its own state
- Immutable infra principles: If EKS cluster config changes, the entire cluster is replaced (not modified)
- Blue-green patterns: Old infrastructure exists until new is validated, then traffic switches
- stateful resource handling. Use deletion_protection_enabled = var.flavour == "PROD" ? true : false

## DB

- Databases are **conditionally created** for certain services: adminservices, pki, subscription, equipment-identity, only if they are enabled.

- RDS ARN is passed to IAM for access control
- RDS Enhanced Monitoring role allows RDS to write metrics to CloudWatch

## IAM

One module **Creates service roles** with trust policies for EKS pods
Another module creates service specific policies and **Attaches policies to roles**
- Why: Each Kubernetes pod assumes an IAM role to access AWS resources (S3, RDS, Lambda, Neptune, etc.)

- IAM Access: Services get S3 ARNs passed via resources_arn_map["service"].buckets to the IAM policies module for read/write permissions.

## S3

Multiple S3 buckets  are created in a data-driven (via for_each loop over local.all_buckets_list) and also using conditional creation.

One-liner: it means buckets are declared as data (a list/map) and Terraform iterates over that data to create resources, instead of writing one resource block per bucket.
