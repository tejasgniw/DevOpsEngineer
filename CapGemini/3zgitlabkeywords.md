### Gitlab key words:

## Core Structure Keywords

- stages: Stages define pipeline flow. (jobs run stage by stage unless there is **needs**, where downstream job can run based on it's dependencies).

- default: Sets default configuration (image, tags, retry, etc.) applied to all jobs unless overridden.

- variables: Defines environment variables available to jobs in the pipeline.

- include: Imports **external CI/CD configuration files/templates** or **reusable components** into the pipeline.


## Job Execution Keywords

- before_script: Commands executed before the main script of a job (used for setup).

- script: The main commands that define what the job actually executes.

- after_script: Commands executed after the main script, regardless of job success or failure.


## Control & Logic Keywords

- rules: Defines conditional logic to determine when a job runs.

- when: Controls job execution timing (e.g., manual, always, never, on_success, delayed).

- allow_failure: Allows a job to fail without failing the entire pipeline.

- only: Specifies branches, tags, or refs or **variables** where a job should run (older syntax).

- except: Specifies branches or refs or **variables** where a job should NOT run (older syntax).


## Parallelism & Optimization

- parallel: Runs **multiple instances of the same job** simultaneously. e.g. for scanning vulnerabilities of multiple images at once by splitting in multiple jobs.

- parallel:matrix, Creates **multiple job variations** dynamically using **different variable combinations**.

- needs: Defines job dependencies and allows downstream jobs to start before the entire previous stage completes.

- resource_group: Ensures only one job using the same resource runs at a time (prevents race conditions).


## Artifacts & Caching

- artifacts: Files generated by a job that are stored and passed to later jobs.

- artifacts:paths, Specifies which files or directories to store as artifacts.

- artifacts:expire_in, Defines how long artifacts are kept.

- cache: Stores dependencies between pipeline runs to improve speed.

- cache:key, Defines a unique identifier for cached content.

| Feature    | Cache                          | Artifacts                    |
| ---------- | ------------------------------ | ---------------------------- |
| Purpose    | Reuse dependencies across jobs | Persist build outputs        |
| Lifetime   | Between pipeline runs          | Between stages, uploadable   |
| Visibility | Only to jobs in same project   | Downloadable via UI / API    |
| Example    | `node_modules`, `.m2/repo`     | `dist/`, `coverage/`, `.jar` |

In the example below, first pipeline runs and downloads all node_modules and stores them under node-modules, the next pipeline runs restores node_modules from cache, skipping the npm install step, thus 

```
stages:
  - build

build_app:
  stage: build
  image: node:18
  script:
    - npm install
    - npm run build
  cache:
    key: node-modules
    paths:
      - node_modules/
```

Cache is specific to the project, not global. Cache is temporary, unlike artifacts which are meant for long-term storage. You can make it branch-specific using key: $CI_COMMIT_REF_NAME.


## Environment & Deployment

- environment: Defines a deployment target (e.g., dev, qa, prod).

- environment:name, Specifies the name of the deployment environment.

- environment:url, Defines the URL of the deployed application.

- environment:action, Used to stop or manage an environment (e.g., stop).

- on_stop: Defines a job that will stop/clean up the environment.

```
automated:launch:ephemeral:environment:
  stage: deploy
  extends: .setup
  environment:
    name: ${CI_COMMIT_REF_NAME}
    url: https://exchange.$CI_COMMIT_REF_NAME.exfodevlab.com.com
    on_stop: close_merge_request_job
  script:
    - terraform plan -out=t.plan -var-file=sandbox.tfvars
    - terraform apply t.plan
  rules:
    - if: $CI_PIPELINE_SOURCE == "trigger"
      when: always
    - when: never

close_merge_request_job:
  stage: deploy
  extends: .setup
  environment:
    name: ${CI_COMMIT_REF_NAME}
    url: https://exchange.$CI_COMMIT_REF_NAME.exfodevlab.com.com
    action: stop
  script:
    - terraform destroy -auto-approve -var-file=sandbox.tfvars
  rules:
    - if: $CI_COMMIT_REF_NAME =~ /^env-.*/
      when: manual
```


## Security & Identity

- id_tokens: Defines OIDC tokens issued by GitLab for secure cloud authentication.

- secrets: Injects secrets securely from GitLab’s secret management.


## Execution Environment

- image: Defines the Docker image used to run the job.

- services: Defines additional containers needed (e.g., database).

- tags: Specifies which GitLab runner should execute the job.


## Pipeline Flow

- workflow: Controls whether a pipeline should be created at all.

```
# Workaround to prevent running detached + regular pipeline
workflow:
  rules:
    # Do run detached MR pipelines
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    # Do run pipelines for schedules on the default branch
    - if: $CI_PIPELINE_SOURCE == "schedule" && $CI_COMMIT_BRANCH == "$CI_DEFAULT_BRANCH"
    # Do run manually or push triggered pipelines on the main branch
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
    # Do not run any other pipelines
    - when: never
```

- extends: Allows a job to inherit configuration from another job template.

```
.on_mr_only:
  rules:
    - if: $CI_PIPELINE_SOURCE == 'merge_request_event'
      when: always
    - if: $CI_COMMIT_BRANCH == "main"
      when: never

terraform:fmt:
  stage: test
  extends: .on_mr_only
  script:
    - terraform fmt -check -recursive
```

- trigger: Starts downstream pipelines in same or another project e.g. Parent-Child pipeline

```
auto-pipeline-system-test:
  stage: systemtest
  variables:
    SETUP_PROJECT_ID: $CI_PROJECT_ID
    SETUP_JOB_ID: $SETUP_JOB_ID
    SETUP_TRIGGER_BRANCH: $CI_COMMIT_BRANCH
    PREVIOUS_VERSION_PACKAGE: $PREVIOUS_VERSION_PACKAGE
    MODE: $MODE
    OA_SC: $OA_SC
    OA_STORAGE_TYPE: $OA_STORAGE_TYPE
    AUTO_UPGRADE: $AUTO_UPGRADE
    REVEAL: $REVEAL
  needs:
    - job: build-internal-package
    - job: test-vogo
  trigger:
    project: exfo/products/asa/sensai/core/systemtest
    branch: $BRANCH_SYSTEMTEST_TO_USE
    strategy: depend
  rules:
    - if: $SKIP_SYSTEMTEST=="true"
      when: never    
    - if: $CI_COMMIT_TAG
      when: never
    - if: $CI_PIPELINE_SOURCE == "merge_request_event" || $CI_MERGE_REQUEST_DRAFT
      when: never
    - if: '$CI_COMMIT_BRANCH=="master" || $CI_COMMIT_BRANCH=="release" || $CI_COMMIT_BRANCH =~ /^release-/ || $CI_OPEN_MERGE_REQUESTS || $AUTOPIPELINE=="true"'
```
